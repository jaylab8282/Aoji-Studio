## 1. 계약 (api-spec)
- 경로 `POST /api/workflows/{workflow}/members` + `encodeURIComponent(target)` — 테스트가 `/api/workflows/%EA%B0%9C%EB%B0%9C%EB%B6%80%EC%84%9C/members`로 단언. 일치
- 요청 `{ members: [{name, role}] }` — api-spec 인라인 스키마와 일치. `minItems: 1`은 0명 버튼 비활성으로 충족
- 200 `{ added, rejected, workflow }` — `ImportMembersResponse`가 `required: [added, rejected, workflow]` 그대로. `rejected[].reason` enum 3값을 `ImportRejectedReason`으로 정확히 옮김
- 400 `fields.members` → 하단 표시 / 409 `LEAD_EXISTS`·404 `WORKFLOW_NOT_FOUND`·403 `READ_ONLY`·500 `IO_FAILED` → `message` 표시(공통 경로). conventions §4 MUST(`fields` 있으면 필드, 없으면 에러 영역) 준수
- **계약에 없는 필드 가정 없음**. 응답의 `workflow`를 직접 스토어에 쓰지 않고 SSE `registry`에 맡기는 것도 realtime-spec §5·ui-spec 에러 열과 일치

## 5. 공유 컴포넌트 회귀
- **`Dialog` `size`**: `SIZE_CLASSES.md = "max-w-md"`이고 `size = "md"`가 기본값이므로 기존 렌더 문자열(`w-full max-w-md rounded-card bg-card p-card-lg`)과 **문자 그대로 동일**. 05-L·05-3·`ConfirmByNameDialog`는 `size`를 넘기지 않으므로 회귀 없음. 해당 테스트 전부 통과
- **`SummaryBar`**: `registry.agents.filter(a => a.workflow === null).length` → `outsideAgents(registry.agents).length`. `outsideAgents`는 같은 술어로 `filter` 후 새 배열에만 `sort`하므로 **개수 동일·입력 비변경**(`[FR-009-AC1] 입력 배열을 바꾸지 않는다`가 단언). T-015 산출물 회귀 없음
- **`search.ts`**: `searchWorkflows`·`matchesQuery` 무변경, `searchAgents`만 추가. T-015·T-016 검색 테스트 전부 통과
- **`DialogHost`**: 기존 분기 사이에 `name === "import"` 분기 1개만 추가. `useDialog` 구조 무변경. 05-L·05-3 테스트 그대로 통과
