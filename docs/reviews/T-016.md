## 1. ADR-17 / D-008 적용 범위 — 구현이 문서에 부합, 결함 아님
- **표시 고정 범위**: `lib/derive/collectorDown.ts`의 `displayStatus(status, collectorDown)`가 ADR-17 문구를 그대로 옮겼고, 호출부는 `Office.tsx:110·117·118·125·139·140`(셔츠·모니터·말풍선·상태 글자)과 `Panel.tsx:121·122`(`상태`·`현재 도구`)뿐. `세션 시작`·`서브에이전트`·`작업 폴더`는 값 그대로(ui-spec SCR-03 패널 행 일치)
- **02 유지 증명 테스트는 실효성 있음**: `Office.test.tsx:289`가 `hookConfigured:false` + `dev-lead:running` **같은 스냅샷 객체**로 02를 렌더해 ① 책상 글자 `작업 중` ② `DeskSprite` rect[4] fill === `shirt.running` ③ 스토어 status === `running` 세 가지를 단언. 바로 앞 `Office.test.tsx:258`이 **같은 입력**으로 03을 렌더해 전원 idle·`대기`·패널 `현재 도구 -`를 단언 → 두 테스트가 쌍으로 구분을 증명. 약한 검증 아님
- **버튼 비활성에 `live.status`를 쓴 판단은 타당**: ui-spec SCR-03 `정의 수정`/`제거` 행의 데이터 출처가 `live.agents[name].status`로 명시돼 있고 에러 열도 `status ≠ idle → 비활성`. ADR-17은 고정 대상을 캐릭터·상태 글자·패널 `상태`·`현재 도구`로 **열거**하며 버튼은 없음. 표시 상태로 버튼을 활성화하면 **열리자마자 서버가 `AGENT_BUSY`로 거부하는 팝업**이 열려 FR-011-AC5를 정면 위반. 04-4 캡처의 `상태 대기` + `작업 중에는 …`은 문서대로 구현한 결과 → 다만 문서 명시 필요(A-1)
