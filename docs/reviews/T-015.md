## KNOWN ISSUE 판정
### 1. 책상 열 수 → [Major] 결함. architect 문서 확정 **불필요**(권장만)
기준 PNG 실측: A(span-3) 폭 1106 / pitch 123.0(8구간 전부 동일) / **9열**, B·C·D(span-1) 폭 344 / pitch 86.3 / **4열**. 즉 **책상 열은 카드 폭을 균등 분할**하며 pitch는 열 수에서 파생된다.
개발자 주장 전반부(고정 gap으로 재현 불가)는 **성립** — A가 9열이려면 pitch ∈ (109.7, 122.9], B가 4열이려면 ∈ (66.4, 83]으로 구간이 겹치지 않는다.
그러나 "ui-spec 규칙이 필요하다"는 결론은 **불성립**. 필요한 건 구현 방식 교체다. 현재 `flex flex-wrap`이라 **항목 폭이 이름 글자 길이를 따라가** 같은 344px 카드인데 B(`video-lead`)는 2열, C(`mkt-lead`)는 3열이 된다. 기준 PNG는 이름 길이와 무관하게 카드마다 pitch가 일정하다.

### 2. 기본 화면 스크롤 → [Minor], 현상 자체는 **결함 아님**
ADR-23이 층 스크롤 영역을 설계로 확정했고 ui-spec "확정된 차이 2"가 스크롤 시 기준 PNG를 판단 근거에서 제외했다. 콘텐츠가 부푼 원인 3가지 중 ① 책상 열 수 = M1로 해소 ② `삭제` 버튼 별도 줄 = **ADR-25 허용 범위, 결함 아님**(344px 카드에 4버튼+사유가 한 줄에 못 들어감. 더 조밀한 배치를 요구할 문서 근거 없음) ③ 책상 줄 세로 pitch = m1(후속).
