## 2. 공격자 관점 점검 (중점 1)

실제 서버를 임시 포트에 띄우고 적대적 입력을 넣어 확인했다(실행은 주입된 가짜 `openTerminal`로 기록만 한다).

### 2.1 명령 문자열에 닿는 입력 경로
명령 문자열은 `buildCommand(projectDir, target, leadName)` 한 곳에서만 만들어지고 삽입값은 **정확히 2개**다.
- `projectDir` — 기동 시 1회(`parseArgs` → `assertSafeProjectDir`), `createHelperServer` 생성 시 1회, `buildCommand` 안에서 매 요청 1회, 3중 검사. 요청 본문에서는 절대 오지 않는다.
- `leadName` — `parseOpenRequest`에서 `^[a-z0-9-]{1,64}$`를 통과한 뒤에만 넘어가고, `buildCommand`가 `isValidLeadName`으로 **한 번 더** 검사한다(우회 경로 없음).

요청 본문의 다른 키는 전부 무시된다. 실측: `{"target":"default","projectDir":"/etc","command":"rm -rf /","leadName":"x;id"}` → 204이고 실행 명령은 `cd "<검증된 dir>" && claude`(주입 흔적 없음). `__proto__` 삽입 → 오염 없음(`{}.polluted`는 undefined). 배열 본문 → 400 `INVALID_BODY`.

### 2.2 AppleScript 이스케이프 (핵심)
팀장이 우려한 `cd "<dir>" && claude`가 AppleScript 문자열 리터럴로 안전한가 하는 문제는 **발생하지 않는다**. 구현이 명령을 AppleScript 소스에 문자열 보간하지 않기 때문이다.

```
spawn('/usr/bin/osascript',
  ['-e','on run argv','-e','tell application "Terminal"','-e','activate',
   '-e','do script (item 1 of argv)','-e','end tell','-e','end run',
   command])
```

`-e`로 넘기는 6줄은 **전부 고정 상수**이고 명령은 argv 마지막 항목으로 런타임에 전달되어 `item 1 of argv`라는 AppleScript **값**으로만 쓰인다. AppleScript 파서가 명령 문자열을 다시 읽지 않으므로 AppleScript 이스케이프 문제가 생길 지점이 없다. architecture.md §7.2 / ADR-11이 지정한 형태와 문자 단위로 일치한다.

남는 해석 계층은 Terminal.app `do script`가 명령 문자열을 셸에 넘기는 한 곳이다. 방어:
- `projectDir`는 큰따옴표 안에 들어가고, 큰따옴표 안에서 의미를 갖는 `"`, 백틱, `$`, 역슬래시와 LF·CR을 전부 금지한다. 큰따옴표 안에서는 `;`, `&`, `|`, 괄호, `*`, 공백이 모두 리터럴이므로 **금지 목록이 충분하다**. 팀장이 물은 백틱·`$( )`·역슬래시·개행은 모두 차단되고 `;`는 큰따옴표 안이라 무해하다. 실측으로 `` /tmp/a`b ``, `/tmp/a$b`, 역슬래시 포함 경로, 개행 포함 경로, `bad"dir` 모두 기동 실패.
- `leadName`은 따옴표 없이 붙지만 문자 집합이 `[a-z0-9-]`뿐이라 셸 메타문자가 원천적으로 없다.

## 4. 개발자 자기 보고 3건 판정 (중점 4·6)

### (a) spawn 옵션에 `shell` 키를 넣지 않았다 → **타당. 판정에 영향 없음 (Minor 기록)**
- tasks.md T-020 Done when이 요구한 단위 테스트 이름이 **"shell 옵션 없음"**이고 테스트가 `!('shell' in options)`로 그대로 단언한다. 태스크 계약은 충족.
- conventions.md §3과 ADR-11의 표기는 `shell: false`다. 다만 그 MUST의 명시된 이유는 FR-013-AC11(셸 조합 금지)이고 Node `spawn`의 `shell` 기본값이 false이므로 **보안 의도는 정확히 달성**된다. `shell: true`가 될 수 있는 경로가 없다.
- 즉 어느 쪽도 결함이 아니라 **문서 간 표기 불일치**다. 더 구체적인 태스크 계약(tasks.md Done when)을 따른 판단이 맞다. 문서 정합은 architect가 한 줄 정리하면 된다(Minor-1).

### (b) `spawn` 이벤트에서 204, 종료 코드 미대기 → **타당. 오히려 이 설계가 맞다**
- FR-013에 종료 코드를 확인하라는 AC·E가 없다. api-spec의 500 `OPEN_FAILED` 설명은 "osascript 실행 실패"이고 실행 자체를 시작하지 못한 경우(ENOENT 등)가 여기 해당한다 — 구현이 이를 덮고 테스트도 있다.
- 더 중요한 근거: FR-013-AC9가 **프론트에 2초 타임아웃**을 요구한다. 종료 코드를 기다리면 macOS 자동화 권한(TCC) 대화상자가 떠 있는 동안 응답이 매달려 2초를 넘기고, 프론트는 "도우미 미설치"(FR-013-E1)라는 **사실과 다른 안내**를 띄우게 된다. 지금 설계가 FR-013-AC9·E1과 충돌하지 않는 선택이다.
- 대가: 자동화 권한 거부처럼 osascript가 **떠서 실패**하는 경우 브라우저는 204를 받는다. 자동 검증으로 덮을 수 없으므로 아래 H-3-5에 사람이 눈으로 볼 항목으로 명시했다.

### (c) plist에 StandardOutPath·StandardErrorPath·ProcessType 추가 → **타당. NFR-08 충돌 없음**
- Done when은 필수 키를 열거했을 뿐 다른 키를 금지하지 않는다. `KeepAlive true`로 상시 재기동되는 LaunchAgent에서 실패 원인을 남길 곳이 없으면 운용이 불가능하므로 근거 있는 추가다. `ProcessType Background`도 상시 백그라운드 서비스에 맞다.
- NFR-08 충돌 없음을 실측했다: 운영 경로(plist 경로, `--dry-run` 없음)에서 stdout에 나가는 것은 `jaystudio-helper listening on http://127.0.0.1:4181` 한 줄, stderr는 기동 실패 한 줄뿐이고 **토큰 값도 요청 본문도 포함되지 않는다**(로그 grep 0건). 토큰 관련 에러 메시지도 값이 아니라 형식만 말한다.
- 명령 문자열을 기록하는 유일한 경로인 `--dry-run`은 렌더러가 plist 진입을 예외로 막으므로 로그 파일에 명령이 남을 경로가 없다.

### JAYSTUDIO_LAUNCH_AGENTS_DIR 판정 (중점 4)
**보안 구멍이 아니다.** 이 변수는 사용자가 직접 실행하는 셸 스크립트가 읽고, 결과는 "plist를 어느 폴더에 쓰고 어느 경로로 bootstrap 하느냐"뿐이다. 변수를 심을 수 있는 주체는 이미 그 사용자의 셸에서 임의 명령을 실행할 수 있으므로 권한 경계를 넘지 않는다. bootstrap 대상은 여전히 `gui/$(id -u)`로 고정이라 도메인도 넓어지지 않는다. `usage()`에 문서화되어 있고, 이 변수 덕분에 테스트가 실제 `~/Library/LaunchAgents`를 건드리지 않는다(자동 구간 절대 제약 준수). 다만 잘못된 값이 남아 있으면 로그인 시 자동 기동이 안 되는 운용상 함정은 있으므로 기본 경로가 아닐 때 경고 한 줄을 찍는 정도는 권장한다.

## 6. SUGGESTIONS (판정과 무관)

1. `leadName`에 선두 하이픈이 허용된다(`-rf`, `--help` → 204, 명령은 `claude --agent --help`). FR-013-AC7의 `^[a-z0-9-]+$`를 그대로 따른 결과라 **스펙 준수이며 셸 주입이 아니다**. 값 출처도 registry의 에이전트 이름이다. 정규식을 `^[a-z0-9][a-z0-9-]{0,63}$`로 좁힐지는 architect 판단 사항.
2. Host 헤더 검사 추가(수용값 `127.0.0.1:<port>`). 지금도 Origin 검사로 DNS rebinding이 막히는 것을 실측 확인했으므로 심층 방어 목적의 선택 사항이다.
3. 기본 경로가 아닌 JAYSTUDIO_LAUNCH_AGENTS_DIR로 설치할 때 install.sh가 경고 한 줄을 남기면 좋다.
4. `jaystudio-helper.mjs`는 shebang이 있으나 실행 권한이 없다(644). plist·테스트 모두 `node <script>`로 실행하므로 동작에는 문제가 없다. shebang을 빼거나 실행 권한을 주는 쪽으로 맞추면 깔끔하다.
5. 로그 파일에 회전이 없다. 한 번 기동에 한 줄이라 실사용상 문제는 없지만 기동 실패 루프에서는 계속 쌓인다(Minor-5를 고치면 자연히 해소).

```bash
./uninstall.sh --dry-run          # 지울 대상만 출력, 아무것도 바꾸지 않는다
```

```bash
TOKEN=$(cat /Users/jaybee/Desktop/JayStudio/.jaystudio/helper-token)
curl -si -X POST http://127.0.0.1:4181/open \
```

기대: `HTTP/1.1 204`. **Terminal.app이 새 창으로 뜨고** `cd "/Users/jaybee/Desktop/JayStudio" && claude`가 실행된다.

```bash
curl -si -X POST http://127.0.0.1:4181/open \
```

### H-3-8. 재부팅 자동 기동 (RunAtLoad·KeepAlive)
로그아웃 후 재로그인 또는 재부팅하고 `curl -s -H 'Origin: http://127.0.0.1:4180' http://127.0.0.1:4181/health` → `{"ok":true,"version":"1"}`.
로그 확인: `tail -5 ~/Library/Logs/com.jaystudio.helper.log` → `jaystudio-helper listening on http://127.0.0.1:4181` 줄만 보여야 하고, **토큰 값이 보이면 결함**(NFR-08).

### H-4. 같은 공유기의 다른 기기에서 접속 불가 (NFR-04)
맥북에서 IP 확인: `ipconfig getifaddr en0` (예: 192.168.0.237)
다른 기기(휴대폰·노트북)에서:
```bash
nc -vz 192.168.0.237 4180
nc -vz 192.168.0.237 4181
```
기대: 둘 다 Connection refused 또는 타임아웃. 브라우저로 `http://192.168.0.237:4181/health`를 열어도 연결되지 않아야 한다. 하나라도 열리면 **NFR-04 결함**.
참고: 리뷰어가 맥북 자신의 LAN IP로 임시 포트에 접속을 시도했을 때는 연결이 거부됐다. 다른 기기에서의 확인만 남았다.


## 8. NEEDS CONFIRMATION

- 위 H-3(Terminal.app 실제 실행·권한 대화상자 동작·재부팅 자동 기동)과 H-4(타 기기 접속 차단)는 사람 확인 전까지 FR-013-AC11·NFR-04의 **최종** 근거가 아니다. 자동 구간에서 확인 가능한 부분(argv 계약, 검증 로직, 실제 listen 주소, 로컬 외부 IP 접속 거부)은 전부 통과했다.
- `--dry-run` 응답 204는 api-spec에 명시돼 있으나, 운영 상태에서 osascript가 **비정상 종료**했을 때의 계약(204 유지)은 문서에 명시가 없다. 결함으로 보지 않았으나(§4(b)) api-spec `/open` 500 설명에 "실행 시작 실패에 한한다"는 한 줄을 넣을지는 architect 확인 사항이다.
