## Overview

Jay Studio는 맥북에서 Docker 컨테이너로 실행하는 **개인용 Claude Code 에이전트 관제 웹**이다.
재사용 에이전트는 `JayStudio/.claude/agents/`에 한 번만 정의하고, 개발 같은 실제 작업은 `JayStudio/<프로젝트명>/` 폴더에서 진행한다.
Jay Studio는 Claude Code hook 이벤트로 에이전트별 실행 상태를 받아 워크플로우(부서) 단위의 층 뷰와 픽셀 오피스로 보여주고, 에이전트 정의 파일과 워크플로우 구성을 웹에서 관리한다.
**웹은 에이전트를 실행하거나 작업을 지시하지 않는다.** 작업 지시는 사용자가 터미널에서 각 워크플로우의 팀장 에이전트에게 직접 한다.
외부 접속 없이 맥북의 `127.0.0.1`에서만 접근한다.

## Goals

- 에이전트마다 `작업 중` / `권한·입력 대기` / `대기`를 실시간으로 구분해 보여준다.
- 에이전트를 워크플로우(부서)로 묶어 층 뷰와 픽셀 오피스로 보여준다. 워크플로우마다 팀장 1명을 첫 자리에 둔다.
- 에이전트 정의 파일을 웹에서 만들고, 수정하고, 워크플로우에서 제거(휴지통 이동)한다.
- 버튼으로 맥북 기본 터미널을 연다. 02 헤더는 기본 세션(`claude`), 03의 `팀장 호출`은 그 워크플로우 팀장 세션(`claude --agent <팀장 name>`)이다.
- 로그인 없이 쓰되, 맥북 밖이나 다른 로컬 웹페이지에서 조작할 수 없게 한다.

## 용어

| 용어 | 뜻 |
|---|---|
| 프로젝트 폴더 | 컨테이너에 마운트한 `JayStudio` 폴더 1개. 웹에서 바꿀 수 없다 |
| 정의 파일 | `JayStudio/.claude/agents/<name>.md`. Claude Code 서브에이전트 정의. 원본은 파일이다 |
| 정상 정의 파일 | FR-002 형식 검증을 통과한 정의 파일 |
| 워크플로우 (부서) | 팀장 1명과 팀원으로 이루어진 에이전트 묶음. `JayStudio/.jaystudio/teams/<이름>.json`에 저장한다 |
| 구성 파일 | 워크플로우 1개의 이름·설명·팀장·팀원 목록을 담는 `teams/<이름>.json` |
| 층 | 02 화면에서 워크플로우 하나를 표시하는 영역 |
| 팀장 | 워크플로우당 1명. 층과 오피스의 첫 자리. 사용자가 `claude --agent <팀장 name>`으로 실행해 작업을 지시한다 |
| 팀원 | 팀장이 아닌 소속 에이전트 |
| 워크플로우 밖 에이전트 | 정상 정의 파일이지만 어느 워크플로우에도 속하지 않은 에이전트 |
| 로비 | 에이전트 지정 없이(`agent_type` 없음) 실행 중인 메인 세션 표시 영역 |
| 정의 없는 서브에이전트 | 정의 파일이 없는 `agent_type`으로 실행된 서브에이전트 (예: 기본 제공 `Explore`, `general-purpose`) |
| 수집 | Claude Code hook이 보낸 이벤트를 Jay Studio가 받는 것 |
| 수집 주소 | hook이 이벤트를 POST하는 `http://127.0.0.1:<포트>/<경로>` |
| 수집 토큰 | 수집 주소 요청에 필요한 토큰. 서버가 첫 기동 시 생성해 `.jaystudio/`에 보관한다 |
| 열기 도우미 | 맥북 호스트에서 실행되는 작은 프로세스. macOS 기본 터미널에서 `claude` 또는 `claude --agent <팀장 name>`을 여는 동작 하나만 한다 |
| 휴지통 | `JayStudio/.jaystudio/trash/`. 제거한 정의 파일 보관 위치 |
| 실시간 연결 | 브라우저–서버 사이의 SSE 연결 |

## User Scenarios

### 처음 실행
1. 사용자가 `JayStudio` 폴더를 마운트해 컨테이너를 실행하고 `127.0.0.1:<포트>`에 접속한다.
2. 01에 에이전트 수·스킬 수가 나온다. hook 이벤트를 한 번도 받지 않았으면 04-1과 hook 설정 안내가 나온다.
3. 07에서 hook 설정 예시(수집 토큰 포함)를 복사해 `JayStudio/.claude/settings.json`에 직접 넣는다. 웹은 이 파일을 수정하지 않는다.
4. 워크플로우가 0개면 01과 02에 `워크플로우 추가` 카드 한 장만 보인다(04-7).

### 워크플로우 구성
1. 02에서 `+ 워크플로우 추가`를 눌러 이름(예: 개발부서)과 설명을 입력한다.
2. 층의 `가져오기`에서 워크플로우 밖 에이전트를 고르고 역할을 정한다(예: `develop-tech-lead` = 팀장, `architect` = 팀원).
3. 필요한 에이전트가 없으면 `+ 만들기`로 정의 파일을 새로 만들어 이 워크플로우에 넣는다.
4. 팀장이 없으면 층에 `팀장이 없습니다` 경고가 나온다.

### 작업 관제
1. (기획이 필요하면) 02 `Claude 열기 · 기본 세션`으로 터미널을 열고 `/planner <프로젝트명>`으로 요구사항을 확정한다.
2. 기획이 끝나면 개발부서 상세(03)에서 `팀장 호출 · 터미널 열기`를 누른다. `claude --agent develop-tech-lead`가 `JayStudio` 폴더에서 실행된다. 직접 터미널에서 같은 명령을 쳐도 된다.
3. 사용자가 팀장에게 `<프로젝트명>/` 폴더에서 진행할 작업을 지시한다. 웹은 지시에 관여하지 않는다.
4. 팀장이 팀원 서브에이전트를 실행하면 02 책상과 03 캐릭터가 `작업 중`으로 바뀌고, 도구 종류에 따라 타이핑·읽기 동작을 보인다.
5. 에이전트가 권한을 요청하면 주황 말풍선과 `권한 대기`가 나오고 01의 대기 수가 늘어난다. 사용자는 터미널에서 승인한다.
6. 서브에이전트가 끝나거나 팀장이 응답을 마치면 캐릭터가 회색 `대기`로 돌아간다.

### 에이전트 수정·제거
1. 03에서 에이전트를 선택하고 `정의 수정`을 누르면 06이 열린다.
2. 설명, 도구, 모델, 본문, 소속 워크플로우, 역할을 고쳐 저장한다. 그사이 파일이 밖에서 바뀌었으면 06-5가 뜬다.
3. `워크플로우에서 제거`를 누르고 이름을 입력해 확인하면 정의 파일이 휴지통으로 이동한다.

## UI 기준

- UI 기준은 `Jay_Studio/docs/ui/`에 고정한다. 시안 캔버스나 링크를 개발 기준으로 쓰지 않는다.
  - `screens/01-home.png`(1440×1140), `screens/02-workflows.png`(1440×1020), `screens/03-workflow-detail.png`(1440×880) — 확정 화면 (다크)
  - `design-tokens.md` — 색·글꼴·간격·모서리. architect가 코드 설정(Tailwind 테마)으로 옮긴다
  - `ui-rules.md` — 상태 표시, 버튼, 빈·로딩·에러·연결 끊김, 민감 정보, 접근성
  - `pixel-sprites.md` — 픽셀 캐릭터 격자·색·동작 표현
  - `screen-flow.md` — 화면 이동
- 시각 디자인은 다크 관제실 톤 단일 테마다. 라이트 테마는 범위 밖이다.
- 확정 화면은 01·02·03 세 개다. 04·05·06·07은 와이어프레임 `docs/JayStudio_Front_Wireframe.pdf`(p.4 = 07, p.5 = 04, p.6 = 05, p.7 = 06)의 구성·요소·흐름을 그대로 쓰고 토큰·규칙만 적용한다. 이 네 화면은 기준 이미지 대신 구성과 규칙으로 리뷰한다.
- 기준 이미지 대조에서 요소 누락, 배치 차이, 흐름 불일치는 결함이다. 1~2px 간격 차이는 결함이 아니다.
- 상태는 색만으로 구분하지 않고 항상 상태 글자를 함께 표시한다.
- 상태가 바뀔 때 색 전환만 200ms 이내로 한다. 움직이는 애니메이션은 없다.

## Functional Requirements

### FR-001 프로젝트 폴더 읽기
- Description: 마운트한 `JayStudio` 폴더에서 `.claude/agents/`, `.claude/skills/`, `.claude/settings.json`, `.jaystudio/`를 읽는다.
- Input: 마운트된 폴더 (웹에서 변경 불가)
- Output: 정상 정의 파일 목록, 스킬 수, 쓰기 가능 여부, 형식 오류 목록, hook 설정 여부
- Acceptance Criteria:
  - FR-001-AC1: 에이전트 수는 `.claude/agents/` 바로 아래 정상 정의 파일(`.md`) 수와 같다.
  - FR-001-AC2: 스킬 수는 `.claude/skills/` 바로 아래에서 `SKILL.md`를 가진 폴더 수와 같다.
  - FR-001-AC3: 웹 밖에서 정의 파일·구성 파일을 추가·수정·삭제하면 `다시 읽기` 없이 2초 이내에 화면에 반영된다.
  - FR-001-AC4: 07과 04-5의 `다시 읽기`를 누르면 즉시 다시 읽고 1초 이내에 응답한다.
  - FR-001-AC5: 07에 마운트 경로를 읽기 전용으로 표시하고, 경로를 바꾸는 입력은 없다.
  - FR-001-AC6: `.jaystudio/`, `.jaystudio/teams/`, `.jaystudio/trash/`가 없으면 첫 쓰기 시점에 서버가 만든다. 읽기만 할 때는 만들지 않는다.
- Error Cases:
  - FR-001-E1: `.claude/agents/`가 없음 → 04-5 (`다시 읽기`, `설정 열기`), 에이전트 수는 표시하지 않음
  - FR-001-E2: 쓰기 권한 없음 → 추가·수정·제거·워크플로우 추가·가져오기 버튼 비활성 + 이유, 07에 `쓰기 권한 없음`
  - FR-001-E3: `.claude/skills/`가 없음 → 스킬 수 0, 에러 아님
- Priority: Must

### FR-002 정의 파일 형식 검증
- Description: 정의 파일 frontmatter를 검사하고, 읽지 못한 파일은 층에 올리지 않고 목록으로만 보여준다.
- Acceptance Criteria:
  - FR-002-AC1: `name` 누락, `name` 형식 위반(`^[a-z0-9-]+$` 아님), frontmatter 형식 오류(YAML 파싱 실패·`---` 구분자 없음), 다른 파일과 `name` 중복, UTF-8 인코딩 오류를 형식 오류로 판정한다.
  - FR-002-AC2: 형식 오류 파일은 층·오피스·에이전트 수·가져오기 목록에서 제외하고 04-6에 파일명과 사유를 표시한다. `name` 중복은 두 파일 모두 사유에 상대 파일명을 적어 표시한다.
  - FR-002-AC3: 형식 오류 파일은 웹에서 편집할 수 없다(04-6에 에디터 수정 안내).
  - FR-002-AC4: `description`이 없는 파일은 형식 오류가 아니라 정상 파일로 취급하고 화면에는 빈 설명으로 표시한다.
  - FR-002-AC5: 구성 파일이 참조하는 name의 정상 정의 파일이 없으면(깨진 참조) 그 항목을 층에서 빼고 04-6 목록에 `<name> · 구성 파일 참조 깨짐 (<워크플로우>)`으로 표시한다. 에이전트 수에는 넣지 않는다.
  - FR-002-AC6: 구성 파일 자체가 JSON 파싱에 실패하면 그 워크플로우를 층에 올리지 않고 04-6 목록에 `<파일명>.json · 구성 파일 형식 오류`로 표시한다.
- Error Cases: 없음 (검증 자체가 오류 처리)
- Priority: Must

### FR-003 hook 이벤트 수집
- Description: 맥북의 Claude Code가 보낸 hook 이벤트를 수집 주소로 받아 에이전트 상태와 실시간 이벤트를 만든다.
- Input: Claude Code `http` hook이 POST하는 JSON (공통 필드 `session_id`, `cwd`, `hook_event_name`, `permission_mode`; 있을 때 `agent_id`, `agent_type`, `tool_name`, `tool_input`, `notification_type`, `message`, `reason`)
- Output: 에이전트별 상태, 실시간 이벤트, 마지막 수신 시각
- Acceptance Criteria:
  - FR-003-AC1: 수집 주소는 `127.0.0.1`에 바인딩된 포트로만 요청을 받는다.
  - FR-003-AC2: 수집 요청은 `Content-Type: application/json`과 유효한 수집 토큰 헤더가 있어야 받는다. 토큰이 없거나 다르면 401로 거부하고 저장하지 않는다.
  - FR-003-AC3: 수집 응답은 2xx에 빈 본문이다(Claude Code 동작에 영향을 주지 않음). 처리는 요청당 100ms 이내에 응답한다.
  - FR-003-AC4: 이벤트의 에이전트는 `agent_type`으로 식별한다. `agent_type`이 정상 정의 파일 name과 같으면 그 에이전트의 이벤트다.
  - FR-003-AC5: `agent_type`이 없는 세션은 로비에 `[세션] · 상태`로 표시한다. 로비 항목은 `session_id`마다 하나이며 `SessionEnd`를 받으면 사라진다.
  - FR-003-AC6: 사이드 탭과 01에 hook 설정 여부와 마지막 수신 시각을 표시한다. 일정 시간 미수신을 이유로 상태를 바꾸지 않는다.
  - FR-003-AC7: 이벤트는 30일 보존하고, 30일이 지난 이벤트는 주기 작업으로 삭제한다.
  - FR-003-AC8: 서버가 꺼져 있거나 응답하지 않아도 Claude Code 작업이 멈추지 않는다. hook 설정 예시는 `type: "http"`, `timeout: 3`을 쓴다(공식 문서: 연결 실패·비 2xx = non-blocking, timeout = hook 취소).
  - FR-003-AC9: 사용 이벤트: `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `Stop`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest`, `PermissionDenied`, `Notification`, `SubagentStart`, `SubagentStop`. 설정 예시는 이 이벤트만 등록한다.
  - FR-003-AC10: 실시간 이벤트 요약은 이벤트 종류별로 정해진 필드에서 만든다: 도구 실행 = `tool_name` + 대상(파일 경로·명령·패턴 중 첫 값), 권한 요청 = `tool_name` + 대상, 세션 시작 = `cwd`, 서브에이전트 시작·종료 = `agent_type`, 응답 종료 = `Stop`. 요약은 200자에서 자른다.
- Error Cases:
  - FR-003-E1: JSON 파싱 실패, `hook_event_name` 누락, 사용하지 않는 이벤트 → 저장하지 않고 2xx로 응답, 서버 로그에 사유만 기록(본문 원문은 기록하지 않음)
  - FR-003-E2: 정의 파일이 없는 `agent_type`(정의 없는 서브에이전트) → FR-007-AC3 작은 캐릭터 / 워크플로우 밖 에이전트의 이벤트 → FR-004-AC7 로비. 두 경우 모두 이벤트는 저장하고 01 실시간 이벤트에 표시한다
- Priority: Must

### FR-004 에이전트 실행 상태
- Description: 에이전트마다 세 가지 상태 중 하나를 표시한다.
- Output: `작업 중`(running) / `권한·입력 대기`(waiting) / `대기`(idle)
- Acceptance Criteria:
  - FR-004-AC1: 상태는 hook 이벤트로만 정한다. 이벤트를 받은 적 없는 에이전트는 `대기`다.
  - FR-004-AC2: 상태 전이표 (세션 단위로 계산한 뒤 에이전트 단위로 합친다):

    | 받은 이벤트 | 조건 | 세션 상태 |
    |---|---|---|
    | `SessionStart` | - | `대기` (같은 `agent_type`의 이전 세션 상태를 모두 정리) |
    | `UserPromptSubmit` | - | `작업 중` |
    | `SubagentStart` | - | 서브에이전트 세션 `작업 중` |
    | `PreToolUse` | `tool_name` ≠ `AskUserQuestion` | `작업 중` |
    | `PreToolUse` | `tool_name` = `AskUserQuestion` | `권한·입력 대기` |
    | `PermissionRequest` | - | `권한·입력 대기` |
    | `Notification` | `notification_type` = `permission_prompt` | `권한·입력 대기` |
    | `Notification` | 그 외 | 상태 변경 없음 |
    | `PostToolUse`, `PostToolUseFailure`, `PermissionDenied` | - | `작업 중` |
    | `Stop` | - | `대기` (세션이 열려 있어도 `대기`) |
    | `SubagentStop` | - | 서브에이전트 세션 `대기` 후 제거 |
    | `SessionEnd` | - | `대기` 후 세션 제거 |
    | 컨테이너 재시작 | - | 모든 세션 제거 → 모두 `대기` |

  - FR-004-AC3: 같은 에이전트가 여러 세션에 동시에 있으면 표시 상태는 `권한·입력 대기` > `작업 중` > `대기` 순으로 우선한다.
  - FR-004-AC4: 서브에이전트의 상태는 `agent_id` 단위로 계산하고, 그 `agent_type`이 정상 정의 파일이면 해당 에이전트의 세션으로 합친다.
  - FR-004-AC5: `멈춤 의심`처럼 시간 경과로 만드는 상태는 없다.
  - FR-004-AC6: 상태가 바뀌면 새로고침 없이 2초 이내에 01·02·03에 반영된다.
  - FR-004-AC7: 워크플로우 밖 에이전트의 이벤트는 로비에 `name · 상태`로 표시한다. 워크플로우에 넣으면 로비에서 빠지고 그 층 책상에 상태가 이어진다.
- Error Cases:
  - FR-004-E1: 순서가 어긋난 이벤트(예: `SessionStart` 없이 `PreToolUse`) → 세션을 그 이벤트로 새로 만들어 처리한다. 거부하지 않는다.
- Priority: Must

### FR-005 홈 요약 (01)
- Description: 전체 관제 요약을 보여준다.
- Output:
  - 실행 중 에이전트 `N / 전체 N`, 권한·입력 대기 수
  - 에이전트 수, 스킬 수, 수집 상태(`hook 설정됨`/`hook 설정 안 됨`, 마지막 수신 시각)
  - 에이전트 상태 막대(3상태 비율과 수)
  - 대표 워크플로우 카드 3개: 이름, 설명, 에이전트·스킬 수, 최근 활동 요약, 칩(`실행 중 N명` / `권한 대기 N명` / `모두 대기`)
  - 실시간 이벤트 표: 시각, 워크플로우, 에이전트, 이벤트, 요약
- Acceptance Criteria:
  - FR-005-AC1: `실행 중 N`은 상태가 `작업 중`인 에이전트 수, `전체 N`은 정상 정의 파일 수, `권한·입력 대기 N`은 상태가 `권한·입력 대기`인 에이전트 수다.
  - FR-005-AC2: 상태 막대의 세 수의 합은 정상 정의 파일 수와 같다.
  - FR-005-AC3: 대표 워크플로우는 `작업 중` 또는 `권한·입력 대기` 에이전트가 있는 워크플로우를 먼저, 그다음 최근 이벤트 시각 내림차순으로 최대 3개다. 이벤트가 없는 워크플로우는 이름 오름차순이다.
  - FR-005-AC4: 워크플로우 카드의 스킬 수는 전체 스킬 수와 같다(스킬은 워크플로우에 속하지 않는다).
  - FR-005-AC5: 워크플로우가 0개면 대표 워크플로우 영역에 `워크플로우 추가` 카드 한 장만 보이고, 누르면 05 왼쪽이 열린다(04-7).
  - FR-005-AC6: 실시간 이벤트는 최신순 최근 50개만 보인다. 전체 로그 화면은 없다.
  - FR-005-AC7: 실시간 이벤트 표의 워크플로우 열은 에이전트가 속한 워크플로우 이름, 로비·워크플로우 밖 에이전트는 `-`다.
  - FR-005-AC8: 이벤트 요약의 민감 값은 FR-015로 가려진다.
  - FR-005-AC9: 첫 로딩 중 숫자 자리는 스켈레톤이다(04-2).
  - FR-005-AC10: `에이전트 워크플로우 열기 →`와 카드의 `워크플로우 보기 →`는 02로 이동한다.
- Error Cases:
  - FR-005-E1: hook 이벤트를 받은 적 없음 → 실시간 이벤트 영역에 04-1과 hook 설정 안내, KPI의 에이전트·스킬 수는 정상 표시
- Priority: Must

### FR-006 에이전트 워크플로우 층 뷰 (02)
- Description: 모든 워크플로우를 층으로, 에이전트를 책상으로 한 화면에 보여준다.
- Output:
  - 상단: 프로젝트 폴더, `127.0.0.1 전용`, `Claude 열기 · 기본 세션`
  - 요약: 에이전트·스킬·워크플로우 수, `워크플로우 밖 에이전트 N · 가져오기`, `+ 에이전트 만들기`
  - 상태 범례와 수, 검색 입력창, 층 선택 드롭다운, `+ 워크플로우 추가`
  - 로비
  - 층 헤더: 이름, 인원, 실행 중·권한 대기 요약, `가져오기`, `+ 만들기`, `상세 →`
- Acceptance Criteria:
  - FR-006-AC1: 팀장은 첫 자리에 `팀장` 배지로 표시하고, 나머지는 name 오름차순(바이트 순 아닌 단순 문자열 오름차순)이다.
  - FR-006-AC2: 층 인원 제한은 없고, 인원이 늘면 층이 세로로 늘어난다. 층 그리드는 3열이고 인원이 많은 층은 가로 3칸을 차지한다(`ui-rules.md` 7).
  - FR-006-AC3: 팀장이 없는 층에는 `팀장이 없습니다 · 팀장을 만들거나 가져오세요` 경고 줄이 나온다.
  - FR-006-AC4: name이 12자를 넘으면 말줄임하고, 마우스를 올리면 전체 name을 보여준다.
  - FR-006-AC5: 워크플로우 단위의 작업 상태는 표시하지 않는다. 층 헤더 요약은 에이전트 수 집계(`실행 중 N명 · 권한 대기 N명`, 둘 다 0이면 `모두 대기`)다.
  - FR-006-AC6: 줌 인·아웃(`+`/`−`), 화면 맞춤(`맞춤`), 미니맵이 동작한다. 줌 범위는 50%~200%다.
  - FR-006-AC7: 층 선택 드롭다운에는 `전체 층 (N개)`과 워크플로우 전체가 들어가고, 고르면 해당 층만 보인다. 워크플로우가 30개여도 상단 바가 줄바꿈으로 무너지지 않는다.
  - FR-006-AC8: 검색창에 입력하면 워크플로우 이름 또는 에이전트 name에 입력값이 부분 일치(대소문자 무시)하는 항목만 남는다. 에이전트가 일치하면 그 층이 남고 일치하는 에이전트만 보인다.
  - FR-006-AC9: 로비에는 `agent_type` 없는 세션을 `[세션 N] · 상태`로 표시한다. 세션이 없으면 `실행 중인 메인 세션 없음` 한 줄이다.
  - FR-006-AC10: 각 책상은 pixel-sprites A 규격(22×22 격자, 46px)이고 name과 상태 글자를 함께 표시한다.
  - FR-006-AC11: 한 에이전트가 두 구성 파일 이상에 있으면 관련된 모든 층에 `<name>이(가) 여러 워크플로우에 있습니다 · 구성 파일을 확인하세요` 경고 줄을 표시하고, 책상은 워크플로우 이름 오름차순 첫 층에만 둔다. 에이전트 수는 1로 센다.
  - FR-006-AC12: 층 헤더에 `삭제` 버튼이 있다. 팀장·팀원이 0명일 때만 활성이고, 아니면 비활성 + `팀원을 먼저 제거하세요`다(FR-017).
- Error Cases:
  - FR-006-E1: `.claude/agents/` 없음 → 04-5
  - FR-006-E2: 형식 오류 파일 있음 → 층 위에 04-6 목록
  - FR-006-E3: 워크플로우 0개 → 04-7
- Priority: Must

### FR-007 워크플로우 상세 · 픽셀 오피스 (03)
- Description: 한 워크플로우의 에이전트를 캐릭터로 보여주고, 선택한 에이전트 정보를 오른쪽 패널에 보여준다.
- Output:
  - 헤더: 워크플로우 이름, 에이전트·스킬 수, `실행 중 N명`, 팀장 name, `팀장 호출 · 터미널 열기`
  - 캐릭터: name, 상태, 현재 동작 말풍선
  - 선택 패널: name, 팀장 배지, 정의 파일 경로, 상태, 현재 도구와 대상 요약, 세션 시작 시각, 서브에이전트 수, 작업 폴더(hook `cwd`), 최근 이벤트
- Acceptance Criteria:
  - FR-007-AC1: 에이전트 1명 = 캐릭터 1개(pixel-sprites B 규격). 팀장 첫 자리, 나머지 name 오름차순. 오피스 그리드는 3열이고 마지막 줄의 빈 칸은 점선 `빈 자리`로 표시한다.
  - FR-007-AC2: 동작 매핑: `Edit`·`Write`·`NotebookEdit` = 말풍선 `타이핑 · <도구>` / `Read`·`Grep`·`Glob` = `읽기 · <도구>` / `권한·입력 대기` = 주황 말풍선 `권한 요청` / `대기` = 회색 `대기` / 그 밖의 도구(`Bash`, `WebFetch`, `Agent` 등) = 말풍선에 `<도구>` 이름 그대로, 셔츠·모니터는 `작업 중` 색.
  - FR-007-AC3: 정의 없는 서브에이전트(`agent_type`이 정상 정의 파일에 없음)는 부모 캐릭터 다음 칸에 작은 캐릭터로 `<agent_type>` name과 `작업 중 · 부모 <name>`을 함께 표시하고 `SubagentStop` 후 사라진다. 정의 파일이 있는 에이전트가 서브에이전트로 실행되면 자기 캐릭터가 `작업 중`이 되고 상태 글자 뒤에 `· 부모 <name>`을 붙인다. 부모는 `session_id`가 같은 `--agent` 세션의 `agent_type`이고, 로비 세션이 부모면 `부모 [세션 N]`이다.
  - FR-007-AC4: 화면에 들어오면 팀장이 선택되어 있다. 팀장이 없으면 첫 자리 에이전트가 선택된다.
  - FR-007-AC5: 선택 패널의 `현재 도구`는 마지막 `PreToolUse`의 `tool_name`과 대상 요약이고, `대기`이면 `-`다. `세션 시작`은 그 에이전트의 가장 최근 `SessionStart`(또는 `SubagentStart`) 시각, `서브에이전트`는 현재 실행 중인 자식 수, `작업 폴더`는 마지막 이벤트의 `cwd`다.
  - FR-007-AC6: 최근 이벤트는 그 에이전트의 최신순 10개다.
  - FR-007-AC7: `정의 수정`, `제거`는 06을 연다. 원문 로그 보기는 없다.
  - FR-007-AC8: `팀장 호출 · 터미널 열기`는 FR-013의 팀장 세션을 연다. 팀장이 없으면 비활성이고 `팀장 없음`을 함께 표시한다.
  - FR-007-AC9: 헤더 `실행 중 N명` 칩은 `ui-rules.md` 1의 워크플로우 칩 규칙을 따른다.
- Error Cases:
  - FR-007-E1: hook 이벤트를 받은 적 없음 또는 hook 설정 없음 → 04-4 (배너 `hook 이벤트 수신 없음 · 마지막 수신 <시각 또는 없음>`, 캐릭터 모두 대기색)
  - FR-007-E2: URL의 워크플로우가 없음 → `워크플로우를 찾을 수 없습니다` + 02로 가는 버튼
- Priority: Must

### FR-009 기존 에이전트 가져오기 (05 오른쪽)
- Description: 워크플로우 밖 에이전트를 골라 워크플로우에 소속시킨다.
- Input: 대상 워크플로우, 에이전트 선택, 에이전트별 역할(팀장/팀원)
- Acceptance Criteria:
  - FR-009-AC1: 목록에는 워크플로우 밖 에이전트만 name 오름차순으로 나온다.
  - FR-009-AC2: 검색창에 입력하면 name·description에 부분 일치(대소문자 무시)하는 항목만 남는다.

  - FR-009-AC4: 팀장은 워크플로우당 1명이다. 대상 워크플로우에 팀장이 있으면 역할 드롭다운에서 `팀장`이 비활성이다.

  - FR-009-AC6: 워크플로우 밖 에이전트가 0명이면 목록 대신 안내와 `+ 새로 만들기`만 보인다.
  - FR-009-AC7: 헤더 `워크플로우 밖 에이전트 N · 가져오기`로 열면 대상 워크플로우를 고르는 드롭다운이 팝업에 있고, 층의 `가져오기`로 열면 그 워크플로우가 고정된다.
- Error Cases:
  - FR-009-E1: 팀장 2명 이상 선택 → 저장 거부, 사유 표시
  - FR-009-E2: 가져오는 사이 다른 워크플로우에 소속됨 → 해당 에이전트만 거부하고 나머지는 저장, 목록 갱신과 사유 표시
  - FR-009-E3: 쓰기 실패 → 구성 파일을 바꾸지 않고 사유 표시
- Priority: Must

### FR-010 에이전트 만들기 (06)
- Description: 폼으로 정의 파일을 만들고 워크플로우에 넣는다.
- Input: name(필수), description(필수), model, 소속 워크플로우(필수), 역할, tools(`전체 상속` / `직접 선택`), 본문(시스템 프롬프트)
- Output: `.claude/agents/<name>.md`, 구성 파일 members 추가
- Acceptance Criteria:
  - FR-010-AC1: name은 `^[a-z0-9-]+$`, 1~64자만 허용하고 정상·형식 오류 파일을 통틀어 중복될 수 없다.
  - FR-010-AC2: tools는 `전체 상속`(frontmatter `tools` 생략)과 `직접 선택`(`Read`, `Grep`, `Glob`, `Edit`, `Write`, `Bash`, `WebFetch`, `WebSearch`, `Agent` 체크박스 + `기타` 직접 입력, 쉼표 구분) 중 하나를 명시적으로 고른다. `직접 선택`에서 0개면 거부한다.
  - FR-010-AC3: model 선택지는 `inherit`(지정 안 함)와 Claude Code 문서가 허용하는 값이다. 목록은 architect가 공식 문서로 확인해 정하고 ui-spec에 적는다.
  - FR-010-AC4: 대상 워크플로우에 팀장이 있으면 `팀장`은 비활성이고 이유를 표시한다.
  - FR-010-AC5: 저장하면 frontmatter에 `name`, `description`, (선택 시) `tools`, (inherit가 아니면) `model`을 쓰고 본문을 붙인다. 저장 후 02로 돌아가고 새 책상이 보인다.
  - FR-010-AC6: 저장 후 "Claude Code가 새 정의를 바로 인식하지 못하면 재시작이 필요할 수 있습니다" 안내를 보여준다.
  - FR-010-AC7: 정의 파일 쓰기와 구성 파일 쓰기가 한쪽만 반영된 채 끝나지 않는다.
- Error Cases:
  - FR-010-E1: 필수값 누락 / name 규칙 위반 / name 중복 → 저장 거부, 필드별 사유
  - FR-010-E2: 쓰기 권한 없음 → 저장 버튼 비활성 + 이유
  - FR-010-E3: 쓰기 중 실패 → 만든 파일을 되돌리고 사유 표시
- Priority: Must

### FR-011 에이전트 수정 (06)
- Description: 기존 정의 파일을 같은 폼으로 수정한다.
- Acceptance Criteria:
  - FR-011-AC1: 폼에 없는 frontmatter 필드(`permissionMode`, `skills`, `hooks`, `disallowedTools`, `memory`, `isolation`, `color` 등)는 값과 순서를 보존한다. 본문은 바이트 그대로 보존한다(줄 끝 변환 없음).
  - FR-011-AC2: name을 바꾸면 파일명이 `<새 name>.md`로 바뀌고 구성 파일 참조도 함께 바뀐다.
  - FR-011-AC3: 소속 워크플로우를 바꾸면 이전 구성 파일에서 빠지고 새 구성 파일에 들어간다(1 에이전트 = 1 워크플로우). 워크플로우 밖 에이전트를 수정할 때는 소속 워크플로우를 비워 둘 수 있다.
  - FR-011-AC4: 저장 직전 파일 수정 시각이 폼을 연 시점과 다르면 06-5를 띄운다. 선택지는 `최신 파일 다시 불러오기`(폼을 다시 채움) / `덮어쓰기`다.
  - FR-011-AC5: 상태가 `작업 중` 또는 `권한·입력 대기`인 에이전트는 수정할 수 없다. 03의 `정의 수정`은 비활성 + `작업 중에는 수정할 수 없습니다`이고, 06이 열린 뒤 상태가 바뀌면 저장 시점에 서버가 거부한다(FR-011-E4). 잔상 상태는 같은 에이전트의 새 `SessionStart` 또는 컨테이너 재시작으로 풀린다(FR-004-AC2).
  - FR-011-AC6: 정의 파일과 구성 파일 중 한쪽만 바뀐 채 끝나지 않는다.
- Error Cases:
  - FR-011-E1: 저장 중 파일이 사라짐 → 저장 거부, 사유 표시
  - FR-011-E2: 새 name이 이미 존재 → 거부, 필드 사유
  - FR-011-E3: 형식 오류 파일을 수정하려 함 → 06을 열지 않고 04-6 안내
  - FR-011-E4: 저장 시점에 에이전트가 `작업 중`·`권한·입력 대기` → 저장 거부, `작업 중에는 수정할 수 없습니다 · 대기가 되면 다시 시도하세요` 표시, 폼 유지
- Priority: Must

### FR-012 워크플로우에서 제거 (06-6)
- Description: 에이전트를 워크플로우에서 빼고 정의 파일을 휴지통으로 옮긴다.
- Acceptance Criteria:
  - FR-012-AC1: 에이전트 name을 정확히 입력해야 제거 버튼이 활성화된다.
  - FR-012-AC2: 정의 파일은 `.jaystudio/trash/`로 이동하고(소프트 삭제), 구성 파일에서 빠진다.
  - FR-012-AC3: 팀장을 제거하면 그 층에 `팀장 없음`이 표시된다.
  - FR-012-AC4: 휴지통에 같은 이름 파일이 있어도 덮어쓰지 않는다. 파일명에 시각 접미사를 붙인다(예: `<name>.<yyyyMMdd-HHmmss>.md`).
  - FR-012-AC5: 워크플로우 밖 에이전트도 03이 아닌 06(수정)에서 제거할 수 있다(휴지통 이동만).
  - FR-012-AC6: 상태가 `작업 중` 또는 `권한·입력 대기`인 에이전트는 제거할 수 없다. 03의 `제거`와 06의 `워크플로우에서 제거`는 비활성 + `작업 중에는 제거할 수 없습니다`이고, 06-6에서 확인하는 시점에 상태가 바뀌면 서버가 거부한다(FR-012-E2).
- Error Cases:
  - FR-012-E1: 이동 실패 → 정의 파일과 구성 파일 모두 원래대로 두고 사유 표시
  - FR-012-E2: 제거 시점에 에이전트가 `작업 중`·`권한·입력 대기` → 제거 거부, 사유 표시, 파일 변경 없음
- Priority: Must

### FR-013 터미널 열기 (기본 세션 / 팀장 호출)
- Description: 맥북 기본 터미널에서 `JayStudio` 폴더 기준으로 Claude Code를 연다. 02 헤더 버튼은 기본 세션, 03 헤더의 `팀장 호출`은 그 워크플로우의 팀장 세션이다. 실행은 맥북 호스트의 열기 도우미가 하고, 브라우저가 도우미를 직접 호출한다.
- Input: 02 `Claude 열기 · 기본 세션` 또는 03 `팀장 호출 · 터미널 열기`
- Output: 맥북 기본 터미널 창
- Acceptance Criteria:
  - FR-013-AC1: 기본 세션의 실행 명령은 `cd "<JayStudio 맥북 경로>" && claude`다.
  - FR-013-AC2: 팀장 호출의 실행 명령은 `cd "<JayStudio 맥북 경로>" && claude --agent <그 워크플로우 팀장 name>`이다.
  - FR-013-AC3: 02에는 팀장 선택 목록을 두지 않는다. 팀장 세션은 해당 워크플로우 상세(03)에서만 연다.
  - FR-013-AC4: 팀장이 없는 워크플로우의 03에서는 `팀장 호출`이 비활성이고 `팀장 없음`을 표시한다.
  - FR-013-AC5: 두 명령은 07에 표시된다.
  - FR-013-AC6: 브라우저는 `http://127.0.0.1:4181`의 도우미를 직접 호출한다. 요청 값은 `기본 세션` 여부와 팀장 name 하나뿐이다. 경로·명령·옵션은 보내지 않는다.

## Definition of Done

### 자동 검증
- 모든 FR의 Acceptance Criteria와 Error Cases가 단위 테스트(Backend·Frontend) 또는 E2E(실제 컨테이너 + fixture 폴더 + 이벤트 재생)로 검증되어 있다.
- 실제 hook 입력 형식의 이벤트 JSON을 재생하면 FR-004-AC2 전이표대로 02·03 상태가 바뀐다.
- 워크플로우 추가, 가져오기, 만들기, 수정, 제거 결과가 fixture 폴더 파일에 정확히 반영되고, 폼에 없는 필드와 본문이 보존된다.
- 04의 7가지 상태가 각 조건에서 표시된다.
- 다른 Origin의 웹페이지에서는 상태 변경 API와 실시간 연결을 쓸 수 없다(E2E).
- 수집 주소는 토큰 없이는 401이다.
- 컨테이너 포트가 `127.0.0.1`에만 공개된다(`docker port` 확인 테스트).
- 01·02·03 구현 화면 스크린샷(1440 폭)과 `docs/ui/screens/*.png`를 리뷰어가 대조해 요소 누락·배치 차이가 없다.

### 사람 확인 (각 1회)
- 실제 `JayStudio` 폴더를 마운트한 컨테이너에 `127.0.0.1`로 접속했을 때 에이전트 수·스킬 수가 실제 파일과 일치한다.
- 07 설정 예시를 `.claude/settings.json`에 붙여 넣고 `claude --agent develop-tech-lead`로 팀장을 실행해 팀원 서브에이전트를 부르면, 02·03 상태가 실제 동작대로 `작업 중` → `권한·입력 대기` → `대기`로 바뀐다.
- 도우미를 설치한 뒤 02 `Claude 열기`와 03 `팀장 호출`로 맥북 기본 터미널에서 `JayStudio` 폴더 기준 `claude` / `claude --agent develop-tech-lead`가 열린다.
- 같은 공유기의 다른 기기에서 Jay Studio 포트에 접속되지 않는다.
- 컨테이너를 끈 상태에서 Claude Code 작업이 멈추지 않는다.
