## Overview

Jay Studio는 맥북에서 Docker 컨테이너로 실행하는 **개인용 Claude Code 에이전트 관제 웹**이다.
재사용 에이전트는 `JayStudio/.claude/agents/`에 한 번만 정의하고, 개발 같은 실제 작업은 `JayStudio/<프로젝트명>/` 폴더에서 진행한다.
지금은 에이전트를 터미널에서만 실행해서 어떤 에이전트가 돌고 있는지, 권한 요청에 막혀 있는지 한눈에 볼 수 없다.
Jay Studio는 Claude Code hook 이벤트로 에이전트별 실행 상태를 받아 워크플로우(부서) 단위의 층 뷰와 픽셀 오피스로 보여주고, 에이전트 정의 파일과 워크플로우 구성을 웹에서 관리한다.
**웹은 에이전트를 실행하거나 작업을 지시하지 않는다.** 작업 지시는 사용자가 터미널에서 각 워크플로우의 팀장 에이전트에게 직접 한다.
외부 접속 없이 맥북의 `127.0.0.1`에서만 접근한다.

## Goals

- 에이전트마다 `작업 중` / `권한·입력 대기` / `대기`를 실시간으로 구분해 보여준다.
- 에이전트를 워크플로우(부서)로 묶어 층 뷰와 픽셀 오피스로 보여준다. 워크플로우마다 팀장 1명을 첫 자리에 둔다.
- 에이전트 정의 파일을 웹에서 만들고, 수정하고, 워크플로우에서 제거(휴지통 이동)한다.
- 버튼으로 맥북 기본 터미널을 연다. 02 헤더는 기본 세션(`claude`), 03의 `팀장 호출`은 그 워크플로우 팀장 세션(`claude --agent <팀장 name>`)이다.
- 로그인 없이 쓰되, 맥북 밖이나 다른 로컬 웹페이지에서 조작할 수 없게 한다.

## User Scenarios

### 처음 실행
1. 사용자가 `JayStudio` 폴더를 마운트해 컨테이너를 실행하고 `127.0.0.1:<포트>`에 접속한다.
2. 01에 에이전트 수·스킬 수가 나온다. hook 이벤트를 한 번도 받지 않았으면 04-1과 hook 설정 안내가 나온다.
3. 07에서 hook 설정 예시를 복사해 `JayStudio/.claude/settings.json`에 직접 넣는다. 웹은 이 파일을 수정하지 않는다.
4. 워크플로우가 0개면 01과 02에 `워크플로우 추가` 카드 한 장만 보인다(04-7).

### 워크플로우 구성
1. 02에서 `+ 워크플로우 추가`를 눌러 이름(예: 개발부서)과 설명을 입력한다.
2. 층의 `가져오기`에서 워크플로우 밖 에이전트를 고르고 역할을 정한다(예: `develop-tech-lead` = 팀장, `architect` = 팀원).
3. 필요한 에이전트가 없으면 `+ 만들기`로 정의 파일을 새로 만들어 이 워크플로우에 넣는다.
4. 팀장이 없으면 층에 `팀장이 없습니다` 경고가 나온다.

### 작업 관제
1. (기획이 필요하면) 02 `Claude 열기 · 기본 세션`으로 터미널을 열고 `/planner <프로젝트명>`으로 요구사항을 확정한다.
2. 기획이 끝나면 개발부서 상세(03)에서 `팀장 호출 · 터미널 열기`를 누른다. `claude --agent develop-tech-lead`가 `JayStudio` 폴더에서 실행된다. 직접 터미널에서 같은 명령을 쳐도 된다.
3. 사용자가 팀장에게 `<프로젝트명>/` 폴더에서 진행할 작업을 지시한다. 웹은 지시에 관여하지 않는다.
4. 팀장이 팀원 서브에이전트를 실행하면 02 책상과 03 캐릭터가 `작업 중`으로 바뀌고, 도구 종류에 따라 타이핑·읽기 동작을 보인다.
5. 에이전트가 권한을 요청하면 주황 말풍선과 `권한 대기`가 나오고 01의 대기 수가 늘어난다. 사용자는 터미널에서 승인한다.
6. 서브에이전트가 끝나거나 팀장이 응답을 마치면 캐릭터가 회색 `대기`로 돌아간다.

### 에이전트 수정·제거
1. 03에서 에이전트를 선택하고 `정의 수정`을 누르면 06이 열린다.
2. 설명, 도구, 모델, 본문, 소속 워크플로우, 역할을 고쳐 저장한다. 그사이 파일이 밖에서 바뀌었으면 06-5가 뜬다.
3. `워크플로우에서 제거`를 누르고 이름을 입력해 확인하면 정의 파일이 휴지통으로 이동한다.

## Functional Requirements

### FR-001 프로젝트 폴더 읽기
- Description: 마운트한 `JayStudio` 폴더에서 `.claude/agents/`, `.claude/skills/`, `.claude/settings.json`, `.jaystudio/`를 읽는다.
- Input: 마운트된 폴더 (웹에서 변경 불가)
- Output: 정상 정의 파일 목록, 스킬 수, 쓰기 가능 여부, 형식 오류 목록, hook 설정 여부
- Acceptance Criteria:
  - 에이전트 수는 `.claude/agents/`의 정상 정의 파일(`.md`) 수와 같다.
  - 스킬 수는 `.claude/skills/` 아래 스킬 수와 같다. (판정 기준: OQ-F6)
  - 웹 밖에서 파일이 추가·수정·삭제되면 `다시 읽기`를 누르지 않아도 정해진 시간 안에 화면에 반영된다. (시간: OQ-F6)
  - 07과 04-5의 `다시 읽기`를 누르면 즉시 다시 읽는다.
  - 07에 마운트 경로를 읽기 전용으로 표시하고, 경로를 바꾸는 입력은 없다.
- Error Cases:
  - `.claude/agents/`가 없음 → 04-5 (`다시 읽기`, `설정 열기`)
  - 쓰기 권한 없음 → 추가·수정·제거·워크플로우 추가 버튼 비활성, 07에 `쓰기 권한 없음`
- Priority: Must

### FR-002 정의 파일 형식 검증
- Description: 정의 파일 frontmatter를 검사하고, 읽지 못한 파일은 층에 올리지 않고 목록으로만 보여준다.
- Acceptance Criteria:
  - `name` 누락, frontmatter 형식 오류, 다른 파일과 `name` 중복, 인코딩 오류를 형식 오류로 판정한다.
  - 형식 오류 파일은 층·오피스·카운트·가져오기 목록에서 제외하고 04-6에 파일명과 사유를 표시한다.
  - 형식 오류 파일은 웹에서 편집할 수 없다(에디터에서 수정 안내).
- Priority: Must

### FR-003 hook 이벤트 수집
- Description: 맥북의 Claude Code가 보낸 hook 이벤트를 수집 주소로 받아 에이전트 상태와 실시간 이벤트를 만든다.
- Input: Claude Code hook 이벤트. 사용 이벤트와 상태 전이: OQ-F2
- Output: 에이전트별 상태, 실시간 이벤트, 마지막 수신 시각
- Acceptance Criteria:
  - 수집 주소는 `127.0.0.1`에서만 요청을 받는다.
  - 이벤트의 에이전트는 hook 입력의 `agent_type`으로 식별한다. `agent_type`은 `claude --agent`로 시작한 세션과 서브에이전트 안에서 들어온다.
  - `agent_type`이 없는 세션은 로비에 `[세션] · 상태`로 표시한다.
  - 사이드 탭과 01에 hook 설정 여부와 마지막 수신 시각을 표시한다. 일정 시간 미수신을 이유로 상태를 바꾸지 않는다.
  - 이벤트는 30일 보존하고, 30일이 지난 이벤트는 삭제한다.
  - Jay Studio가 꺼져 있거나 수집에 실패해도 Claude Code 작업이 멈추지 않는다(`requirements_architecture.md` NFR).
- Error Cases:
  - 형식이 잘못된 이벤트 → 저장하지 않고 무시, 서버 로그에 사유만 기록
  - 정의 파일이 없는 `agent_type`, 워크플로우 밖 에이전트의 이벤트 → 표시 위치 OQ-F4
- Priority: Must

### FR-004 에이전트 실행 상태
- Description: 에이전트마다 세 가지 상태 중 하나를 표시한다.
- Output: `작업 중` / `권한·입력 대기` / `대기`
- Acceptance Criteria:
  - 상태는 hook 이벤트로만 정한다. 이벤트를 받은 적 없는 에이전트는 `대기`다.
  - 권한 요청 이벤트를 받으면 `권한·입력 대기`, 이어서 도구 실행 이벤트를 받으면 `작업 중`이 된다.
  - 서브에이전트 종료, 응답 종료, 세션 종료 이벤트를 받으면 `대기`가 된다. (전이표: OQ-F2)
  - 컨테이너가 재시작되면 모든 에이전트는 `대기`에서 시작한다.
  - `멈춤 의심`처럼 시간 경과로 만드는 상태는 없다.
  - 상태가 바뀌면 새로고침 없이 정해진 시간 안에 01·02·03에 반영된다. (시간: OQ-F6)
- Error Cases: 같은 에이전트가 여러 세션에서 동시에 실행 → 표시 우선순위 OQ-F2
- Priority: Must

### FR-005 홈 요약 (01)
- Description: 전체 관제 요약을 보여준다.
- Output:
  - 실행 중 에이전트 `N / 전체 N`, 권한·입력 대기 수
  - 에이전트 수, 스킬 수, 수집 상태
  - 에이전트 상태 막대(3상태 비율과 수)
  - 대표 워크플로우 카드 3개: 이름, 설명, 에이전트·스킬 수, 최근 활동 요약, 칩(`실행 중 N명` / `권한 대기 N명` / `모두 대기`)
  - 실시간 이벤트 표: 시각, 워크플로우, 에이전트, 이벤트, 요약
- Acceptance Criteria:
  - 대표 워크플로우는 실행 중 에이전트가 있는 워크플로우를 먼저, 그다음 최근 활동순으로 최대 3개다.
  - 워크플로우가 0개면 `워크플로우 추가` 카드 한 장만 보이고, 누르면 05 왼쪽이 열린다(04-7).
  - 실시간 이벤트는 최근 N개만 보인다. 전체 로그 화면은 없다. (N: OQ-F6)
  - 이벤트 요약의 민감 값은 FR-015로 가려진다.
  - 첫 로딩 중 숫자 자리는 스켈레톤이다(04-2).
- Error Cases: hook 이벤트를 받은 적 없음 → 04-1
- Priority: Must

### FR-006 에이전트 워크플로우 층 뷰 (02)
- Description: 모든 워크플로우를 층으로, 에이전트를 책상으로 한 화면에 보여준다.
- Output:
  - 상단: 프로젝트 폴더, `127.0.0.1 전용`, `Claude 열기 · 기본 세션`
  - 요약: 에이전트·스킬·워크플로우 수, `워크플로우 밖 에이전트 N · 가져오기`, `+ 에이전트 만들기`
  - 상태 범례와 수, 검색 입력창, 층 선택 드롭다운, `+ 워크플로우 추가`
  - 로비
  - 층 헤더: 이름, 인원, 실행 중·권한 대기 요약, `가져오기`, `+ 만들기`, `상세 →`
- Acceptance Criteria:
  - 팀장은 첫 자리에 `팀장` 배지로 표시하고, 나머지는 name 오름차순이다.
  - 층 인원 제한은 없고, 인원이 늘면 층이 세로로 늘어난다.
  - 팀장이 없는 층에는 `팀장이 없습니다 · 팀장을 만들거나 가져오세요` 경고 줄이 나온다.
  - name이 12자를 넘으면 말줄임하고, 마우스를 올리면 전체 name을 보여준다.
  - 워크플로우 단위의 작업 상태는 표시하지 않는다.
  - 줌 인·아웃, 화면 맞춤, 미니맵이 동작한다.
  - 층 선택 드롭다운에는 `전체 층`과 워크플로우 전체가 들어가고, 고르면 해당 층만 보인다. 워크플로우 개수가 늘어도 레이아웃이 깨지지 않는다.
  - 검색창에 입력하면 이름이 맞는 워크플로우와 에이전트만 남는다. (검색 대상·일치 방식: OQ-F6)
- Error Cases: 04-5, 04-6, 04-7
- Priority: Must

### FR-007 워크플로우 상세 · 픽셀 오피스 (03)
- Description: 한 워크플로우의 에이전트를 캐릭터로 보여주고, 선택한 에이전트 정보를 오른쪽 패널에 보여준다.
- Output:
  - 헤더: 워크플로우 이름, 에이전트·스킬 수, `실행 중 N명`, 팀장 name, `팀장 호출 · 터미널 열기`
  - 캐릭터: name, 상태, 현재 동작 말풍선
  - 선택 패널: name, 팀장 배지, 정의 파일 경로, 상태, 현재 도구와 대상 요약, 세션 시작 시각, 서브에이전트 수, 작업 폴더(hook `cwd`), 최근 이벤트
- Acceptance Criteria:
  - 에이전트 1명 = 캐릭터 1개. 팀장 첫 자리, 나머지 name 오름차순. 빈 자리는 점선 칸으로 표시한다.
  - 동작 매핑: Edit·Write = 타이핑 / Read·Grep·Glob = 읽기 / 권한 요청 = 주황 말풍선 / 대기 = 회색. (그 밖의 도구: OQ-F6)
  - 에이전트가 실행한 서브에이전트는 작은 캐릭터로 `부모 <name>`과 함께 표시한다.
  - 화면에 들어오면 팀장이 선택되어 있다. 팀장이 없으면 첫 자리 에이전트가 선택된다 (제안).
  - `정의 수정`, `제거`는 06을 연다. 원문 로그 보기는 없다.
  - `팀장 호출 · 터미널 열기`는 FR-013의 팀장 세션을 연다. 팀장이 없으면 비활성이다.
- Error Cases: 수집 중단 → 04-4 (배너, 마지막 수신 시각, 캐릭터 모두 회색)
- Priority: Must

### FR-008 워크플로우 추가 (05 왼쪽)
- Description: 이름과 설명으로 워크플로우를 만든다.
- Input: 이름(필수), 설명(선택)
- Output: `.jaystudio/teams/<이름>.json` (팀장·팀원 목록을 담는 구성 파일)
- Acceptance Criteria:
  - 이름은 중복될 수 없다. 워크플로우 개수 제한은 없다.
  - 팝업에 "팀장이 없으면 층에 팀장 없음이 표시됩니다" 안내가 있다.
  - 만들면 02에 새 층이 바로 나타난다.
- Error Cases: 이름 중복 → 거부 / 파일명으로 쓸 수 없는 문자 → 거부 (허용 문자: OQ-F6) / 쓰기 실패 → 파일을 만들지 않고 사유 표시
- Priority: Must

### FR-009 기존 에이전트 가져오기 (05 오른쪽)
- Description: 워크플로우 밖 에이전트를 골라 워크플로우에 소속시킨다.
- Input: 대상 워크플로우, 에이전트 선택, 에이전트별 역할(팀장/팀원)
- Acceptance Criteria:
  - 목록에는 워크플로우 밖 에이전트만 나온다.
  - name·description으로 검색할 수 있다.
  - 정의 파일은 바꾸지 않고 구성 파일에 소속과 역할만 기록한다.
  - 팀장은 워크플로우당 1명이다. 대상 워크플로우에 팀장이 있으면 `팀장`을 고를 수 없다.
  - 버튼에 선택 인원이 나온다(`선택한 N명 가져오기`).
  - 워크플로우 밖 에이전트가 0명이면 `+ 새로 만들기`만 보인다.
- Error Cases: 팀장 2명 선택 → 저장 거부 / 가져오는 사이 다른 워크플로우에 소속됨 → 해당 에이전트 거부 후 목록 갱신
- Priority: Must

### FR-010 에이전트 만들기 (06)
- Description: 폼으로 정의 파일을 만들고 워크플로우에 넣는다.
- Input: name(필수), description(필수), model, 소속 워크플로우(필수), 역할, tools(`전체 상속` / `직접 선택`), 본문(시스템 프롬프트)
- Output: `.claude/agents/<name>.md`, 구성 파일 members 추가
- Acceptance Criteria:
  - name은 소문자와 하이픈만 허용하고 중복될 수 없다.
  - tools는 `전체 상속`(frontmatter `tools` 생략)과 `직접 선택`(Read, Grep, Glob, Edit, Write, Bash, WebFetch, WebSearch, Agent, 기타 직접 입력) 중 하나를 명시적으로 고른다.
  - model 선택지는 `inherit`와 Claude Code 문서가 허용하는 값이다. 목록은 architect가 공식 문서로 확인해 정한다.
  - 대상 워크플로우에 팀장이 있으면 `팀장`은 비활성이고 이유를 표시한다.
  - 저장하면 02로 돌아가고 새 책상이 보인다.
  - Claude Code가 새 정의를 바로 인식하지 못하면 재시작이 필요할 수 있다는 안내를 보여준다.
- Error Cases: 필수값 누락 / name 규칙 위반 / name 중복 / 쓰기 권한 없음 → 저장 거부와 필드별 사유
- Priority: Must

### FR-011 에이전트 수정 (06)
- Description: 기존 정의 파일을 같은 폼으로 수정한다.
- Acceptance Criteria:
  - 폼에 없는 frontmatter 필드(`permissionMode`, `skills`, `hooks` 등)는 값과 순서를 보존한다.
  - name을 바꾸면 파일명이 `<새 name>.md`로 바뀌고 구성 파일 참조도 함께 바뀐다.
  - 소속 워크플로우를 바꾸면 이전 구성 파일에서 빠지고 새 구성 파일에 들어간다(1 에이전트 = 1 워크플로우).
  - 저장 직전 파일 수정 시각이 폼을 연 시점과 다르면 06-5를 띄운다. 선택지는 `최신 파일 다시 불러오기` / `덮어쓰기`다.
  - `작업 중`인 에이전트도 수정할 수 있다. 경고 표시 여부: OQ-F5
- Error Cases: 저장 중 파일이 사라짐 → 저장 거부 / 새 name이 이미 존재 → 거부 / 정의 파일과 구성 파일 중 한쪽만 바뀐 채 끝나지 않는다
- Priority: Must

### FR-012 워크플로우에서 제거 (06-6)
- Description: 에이전트를 워크플로우에서 빼고 정의 파일을 휴지통으로 옮긴다.
- Acceptance Criteria:
  - 에이전트 name을 정확히 입력해야 제거 버튼이 활성화된다.
  - 정의 파일은 `.jaystudio/trash/`로 이동하고(소프트 삭제), 구성 파일에서 빠진다.
  - 팀장을 제거하면 그 층에 `팀장 없음`이 표시된다.
  - 휴지통에 같은 이름 파일이 있어도 덮어쓰지 않는다.
- Error Cases: 이동 실패 → 정의 파일과 구성 파일 모두 원래대로 두고 사유 표시
- Priority: Must

### FR-013 터미널 열기 (기본 세션 / 팀장 호출)
- Description: 맥북 기본 터미널에서 `JayStudio` 폴더 기준으로 Claude Code를 연다. 02 헤더 버튼은 기본 세션, 03 헤더의 `팀장 호출`은 그 워크플로우의 팀장 세션이다.
- Input: 02 `Claude 열기 · 기본 세션` 또는 03 `팀장 호출 · 터미널 열기`
- Output: 맥북 기본 터미널 창
- Acceptance Criteria:
  - 기본 세션의 실행 명령은 `cd "<JayStudio 맥북 경로>" && claude`다.
  - 팀장 호출의 실행 명령은 `cd "<JayStudio 맥북 경로>" && claude --agent <그 워크플로우 팀장 name>`이다.
  - 02에는 팀장 선택 목록을 두지 않는다. 팀장 세션은 해당 워크플로우 상세(03)에서만 연다.
  - 팀장이 없는 워크플로우의 03에서는 `팀장 호출`이 비활성이고 이유를 표시한다.
  - 두 명령은 07에 표시된다.
  - 맥북 열기 도우미가 설치되어 있을 때만 터미널이 열린다. 도우미가 받는 값은 `기본 세션` 여부와 팀장 name 하나뿐이다.
  - 도우미는 팀장 name이 소문자·숫자·하이픈 형식이 아니면 실행하지 않는다.
  - 도우미가 없거나 응답하지 않으면 선택한 항목의 명령과 함께 미설치 안내·`명령 복사`를 보여준다.
  - 07 `테스트로 열기`는 도우미가 없으면 비활성이다.
- Error Cases:
  - 도우미 미설치·무응답 → 안내와 명령 복사
  - 도우미 인증 실패 → 거부
  - 형식이 잘못된 팀장 name → 도우미가 거부하고 웹에 사유 표시
  - 선택 직후 팀장이 제거되어 정의 파일이 없음 → 실행하지 않고 목록 갱신 (제안)
- Priority: Must

### FR-014 설정 (07)
- Description: 운영 정보를 읽기 전용으로 보여준다.
- Output:
  - 프로젝트 폴더: 마운트 경로, 정의 수, 스킬 수, 쓰기 권한, 형식 오류 수, `다시 읽기`
  - Claude 열기: 터미널 앱(macOS 기본 터미널), 기본 세션 명령, 팀장으로 열기 명령과 도우미 입력 제한 안내, 도우미 설치 여부, `테스트로 열기`, `명령 복사`
  - 수집: 수집 주소, `.claude/settings.json` hook 설정 여부, `설정 예시 복사`, 구성 파일 위치, 휴지통 위치, 이벤트 보존 30일
- Acceptance Criteria:
  - 웹은 `.claude/settings.json`을 쓰지 않는다.
  - `설정 예시 복사`로 복사한 내용을 그대로 붙여 넣으면 이벤트가 수집된다.
  - hook 설정 여부는 `.claude/settings.json`에 수집 주소를 쓰는 hook이 있는지로 판정한다 (제안).
- Priority: Must

### FR-015 민감 정보 마스킹
- Description: 이벤트 요약에 섞인 민감 값을 가린다.

  - 가리기 전 원문은 화면과 API 응답 어디에도 나오지 않는다. (저장 시점 마스킹: architecture OQ-A4)

### FR-016 실시간 연결 끊김 (04-3)
- Description: 브라우저–컨테이너 실시간 연결이 끊기면 알리고 자동으로 다시 연결한다.
- Acceptance Criteria:
  - 모든 화면 상단에 `실시간 연결이 끊겼습니다 · N초 후 재연결` 배너와 `지금 재연결` 버튼이 나온다.

## Definition of Done

- 실제 `JayStudio` 폴더를 마운트한 컨테이너에 `127.0.0.1`로 접속했을 때 에이전트 수·스킬 수가 실제 파일과 일치한다.
- 사용자가 `JayStudio` 폴더에서 `claude --agent develop-tech-lead`로 팀장을 실행하고 팀원 서브에이전트를 부르면, 02·03 상태가 실제 동작대로 `작업 중` → `권한·입력 대기` → `대기`로 바뀐다. (사람이 1회 확인)
- 워크플로우 추가, 가져오기, 만들기, 수정, 제거 결과가 파일에 정확히 반영되고, 폼에 없는 필드와 본문이 보존된다.
- `Claude 열기`로 맥북 기본 터미널에서 `JayStudio` 폴더 기준 `claude`가 열린다. (사람이 1회 확인)
- 04의 7가지 상태가 각 조건에서 표시된다.
- 맥북 밖(같은 공유기의 다른 기기 포함)과 다른 Origin의 웹페이지에서는 API와 실시간 연결을 쓸 수 없다.
- 컨테이너가 꺼져 있어도 Claude Code 작업이 멈추지 않는다.
- 모든 FR의 Acceptance Criteria와 Error Cases가 자동 테스트 또는 위의 사람 확인 항목으로 검증되어 있다.

## Decision Log (사용자 확정 — 재질문하지 않음)

- 형태 → 맥북 로컬 전용 웹, Docker 컨테이너 실행. 외부 접속·서버 배포·로그인 없음.
- 관제 대상 → 마운트한 `JayStudio` 폴더 1개 고정, 경로 변경 기능 없음. 에이전트는 이 폴더에 한 번만 정의해 재사용.
- 작업 폴더 → 실제 작업(개발 등)은 `JayStudio/<프로젝트명>/`에서 진행. Claude Code는 항상 `JayStudio` 폴더에서 시작.
- 팀장 실행 → 팀장은 정의 파일로 두고 `claude --agent <팀장 name>`으로 실행해 사용자가 지시. 개발부서 팀장은 `develop-tech-lead`.
- 웹의 역할 → 관제와 정의·구성 관리만. 에이전트 실행·작업 지시 없음.
- 사이드 탭 → 홈 / 에이전트 워크플로우 / 설정. 로그 탭 없음. 워크플로우 목록은 사이드 탭에 나열하지 않음.
- 홈 → 요약만. 대표 워크플로우 3개(실행 중 에이전트가 있는 워크플로우 → 최근 활동순). 0개면 추가 카드 1장.

- 소속 → 1 에이전트 = 1 워크플로우. 워크플로우당 팀장 1명, 첫 자리. 나머지 이름순. 인원 제한 없음.
- 상태 → 워크플로우 단위 상태 체크 없음. 에이전트별 3상태만 hook 이벤트로 표시. 멈춤 의심 판정 없음.
- 등록 → 새 정의 파일 만들기 또는 워크플로우 밖 기존 정의 파일 가져오기.

- 워크플로우 구성 저장 → `.jaystudio/teams/<이름>.json`. 이름 중복 불가, 개수 제한 없음.
- 정의 수정 → 이름 변경 시 파일명 변경, 폼에 없는 필드 보존, 저장 전 수정 시각 비교로 충돌 확인.

- 로그 → 실시간 이벤트 최근 N개만. 원문·전체 로그 화면 없음. 기본 패턴 마스킹. 이벤트 보존 30일.

- **OQ-F2 [높음] hook 이벤트 → 에이전트 상태 전이표**
  - FR-004를 테스트 가능하게 만드는 표. 제안안:
    - `작업 중`: `UserPromptSubmit`(--agent 세션), `SubagentStart`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`
    - `권한·입력 대기`: `PermissionRequest`, `Notification`(`permission_prompt`, `agent_needs_input`)

  - `Stop` 후 세션이 열려 있는 팀장을 `대기`로 볼지. 제안: `대기`.
  - 터미널 강제 종료처럼 종료 이벤트가 오지 않으면 `작업 중`이 남는다. 시간 기반 판정은 제외했으므로, 같은 에이전트의 새 `SessionStart`를 받으면 이전 세션을 정리할지 확인한다.
  - 같은 에이전트가 여러 세션에서 동시에 돌 때 표시 우선순위. 제안: 권한·입력 대기 > 작업 중 > 대기.
